THE CLIMB · TWO CHALLENGES, ANSWERED BY DESIGN

Design choices we made

FALSE POSITIVES — A DESIGN TARGET, NOT A HOPE
Precision is scoredEvery alert is closed as real or noise; precision = real ÷ all. Target < 20% noise (60–80% today); a red month creates a tuning backlog item.
Baselines earn the right4–6 weeks of learned history before a signal may page; anomaly scores alert, never block.
Shadow before blockThe gate logs what it would hold, holds nothing, and blocks only after precision is proven on real traffic.
Ten signals, one pageAlerting groups by cause — a deploy that breaks five assets pages one team, once, with the cause attached.
WHY BUILD — WHAT NO VENDOR SELLS
Element-level lineageCaptured by static code analysis at merge time. Warehouse monitors see tables; they cannot see the code edges, services, and streams between them.
Deploy correlationCI/CD events joined to evidence under one enterprise-registry URN — deploy introduced failure is the RCA answer a table monitor cannot produce.
An open evidence APIEvery result lands on one bus we own; future tools build on it instead of a vendor's closed store.
Buy the commodityExisting warehouse and team-built checks federate into the same stream unchanged — the join is the build, not the checks.
THE BENCHMARKWarehouse tools say a table looks wrong, hours after it lands. The experience on slide 3 needs more: the causing deploy named at the service and stream layer, before consumers read. That gap is the build — commodity checks plug into the same evidence stream.

THE DECISION · ASKS

Asks, dependencies, assumptions, risks

FROM PRODUCERS — THE TEAMS OWNING THE REPOS
P0–P2Nothing. Zero code changes — detection is out-of-band, read-only, in our account.
P3Review one auto-drafted contract — ~20 minutes, drafted from 90 days of their own observed behavior.
P4 · Tier-1Adopt lineage emitters / in-path asserts — Tier-1 streams only, paired with the platform team.
Adoption cost is deliberately near-zero until the platform has proven value at the gate.
FROM ENTERPRISE TOOLS
P0THE decision: the enterprise registry is the naming authority — URNs come from the managed catalog; pilot's ~10 assets first. Without it every join fails silently later.
P0Streaming platform: read-only credentials + topic catalog + schema registry. Plan B: detect at tables.
M1Central DQ tooling: read access to check results. Plan B: scheduled export, staler.
M4CI/CD: deploy events (commit + timestamp), pilot pipelines only. Plan B: infer from logs.
DEPENDS · ASSUMES · RISKSDepends on: the registry decision, read-only broker + CI/CD access — each dated (weeks 3–4) with a stub fallback. Assumes: pilot volumes ≈ today's; producers stay hands-off until value shows. Risks: adoption stalls → executive merge SLA; noisy alerts → shadow mode + the <20% noise target. Slips surface on the scorecard, never absorbed silently.
CLOSE

Risks and decisions needed

RISKPRs generated but not merged
Mitigation: executive-backed merge SLA, escalation path, visible scorecards.
RISKEvidence too weak for causality
Mitigation: trust tiers — inferred vs platform-attested vs producer-attested; "unknown" is a valid RCA output.
RISKThe platform becomes its own blind spot
Mitigation: observability-of-observability — evidence-gap alerts, lag monitoring, runbooks from day one.
RISKScope expands before value is proven
Mitigation: hard MVP boundary — three engines, one pilot domain, measurable pain first.
DECISIONS NEEDED FROM LEADERSHIP
1Approve this target architecture as the missions' convergence point
2Back the enterprise registry as naming authority now — every join depends on it
3Hold the MVP boundary — month-9 gate scope does not grow
4Fund the target run-rate: ~$21K/month infrastructure at scale
Go/no-go at the month-9 gate: saves banked and time-to-detect down vs the Phase-0 baseline — decided on the scorecard, not on architecture progress.
